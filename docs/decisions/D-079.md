## Decision record

Date: 2026-09-18.

Status: accepted.

Decision: Added ESLint (flat config, `eslint.config.mjs`) as the repository's
correctness/quality gate — `eslint-config-next/core-web-vitals` +
`eslint-config-next/typescript`, `eslint-plugin-jsx-a11y`'s full recommended
set (the Next config alone only wires ARIA-validity rules), and type-aware
`typescript-eslint` promise rules (`no-floating-promises`,
`no-misused-promises`, `await-thenable`, `only-throw-error`) via
`projectService`. `npm run lint` and `npm run check` (lint + typecheck +
`npm test`) are new; CI now runs `npm ci` (not `npm install`) and a `Lint`
step ahead of typecheck/build/Playwright.

`eslint-config-prettier` is wired in (last in the config array) so ESLint's
formatting-adjacent rules don't fight a future Prettier run, but Prettier
itself was not applied: a full-repo run reformats ~476 of ~480 TS/TSX files
regardless of `printWidth`, which is unrelated churn on top of every future
PR's real diff for a long time. No `format`/`format:check` scripts were
added. Stylelint was not added either — `app/globals.css` alone is 14k
lines, and CSS architecture cleanup is explicitly out of scope for a
lint-infrastructure change.

Several rule categories are deliberately staged at "warn" rather than
"error" because the first real lint run found them to be broad, pre-existing
patterns needing per-instance judgment, not isolated mistakes — turning them
on as hard errors immediately would have meant either a suppression
avalanche or an unrelated mass-rewrite, both of which this change is
explicitly trying to avoid:

- `@typescript-eslint/no-explicit-any` (~636 occurrences, ~109 files).
- `@typescript-eslint/no-unused-vars` (~111 remaining after adding
  `argsIgnorePattern`/`varsIgnorePattern: "^_"`, which is how this codebase
  already spells "intentionally unused," e.g. the prescribing adapter stubs).
- `react-hooks/refs`, `react-hooks/immutability`,
  `react-hooks/preserve-manual-memoization`, `react-hooks/set-state-in-effect`
  — `eslint-plugin-react-hooks` v7's `recommended` config bundles the newer
  React Compiler readiness rules as hard errors. The baseline hits are real
  patterns (syncing a ref during render in `useDashboardAutosave.ts` /
  `useAdaptiveLayout.ts` / `RailResizeHandle.tsx`; a `useCallback` closing
  over state declared later in the same component in `PatientWorkspace.tsx`
  and `OrderCartModal.tsx`; a `useMemo` dependency array that doesn't
  structurally match what the compiler infers in `useAdaptiveLayout.ts` and
  `PatientDocuments.tsx`) — working code today, but fixing them means real
  hook-architecture changes, not local edits. `react-hooks/rules-of-hooks`
  stays a hard error; `react-hooks/exhaustive-deps` stays at its upstream
  "warn" default (16 pre-existing misses, all needing per-effect judgment
  about whether adding the dependency changes behavior — several are in
  `PatientWorkspace.tsx`, `CalendarWorkspace.tsx`, and `TodayDashboard.tsx`,
  named explicitly as not-to-be-restructured for this).
- `jsx-a11y/label-has-associated-control` (137, 18 files) — this codebase
  also uses bare `<label>` as a generic field-caption/typography element for
  read-only display fields with no control to associate with at all, not
  only for real form inputs; sorting one from the other is file-by-file work.
- `jsx-a11y/click-events-have-key-events` / `no-static-element-interactions`
  (71 / 60) and `no-noninteractive-element-interactions` (14) — the
  `<div className="modal-backdrop" onClick={onClose}>` click-to-dismiss
  pattern used throughout (e.g. `AuditComplianceModal.tsx`) plus similar
  clickable rows/cards. Every modal in the baseline also has a real
  `<button>` close control, so this is a mouse-only convenience layered on
  an already-keyboard-reachable dismissal rather than a keyboard trap — but
  the correct fix (a shared `ModalBackdrop` primitive with its own key
  handler) is a real component to design, not a per-file patch.

`jsx-a11y/no-autofocus` was turned off outright rather than staged: every one
of its 16 baseline hits is a dialog or inline "add" form's first field
autofocusing on an explicit clinician action (opening the dialog), which is
the WCAG-recommended behavior, not the page-load autofocus anti-pattern the
rule targets.

Fixed immediately as part of this change (small, local, behavior-preserving,
verified against the baseline): unused imports/vars flagged as errors before
the underscore-prefix convention was added; `let` → `const` where never
reassigned; a `require()` inside a function replaced with a top-level
`import` (`document-workflow-foundation.ts`); a handful of local variables
named `module` renamed to `moduleId`/`moduleEntry` (false positives against
`@next/next/no-assign-module-variable`, which exists for the Pages Router
`module.exports` convention this app doesn't use); unescaped `'` in JSX
text; `await` removed from calls to the synchronous
`WorkflowService.createAppointment` in two intake tests; ~14 genuinely
floating promises in application code given `void` (matching the codebase's
existing `void refreshUser();` convention) or, where already-swallowed
errors made the promise safe but the pattern itself opaque to the rule, a
narrow explained `eslint-disable-next-line`; the `useState<any>` health
snapshot in `AuditComplianceModal.tsx` given a real (if partial — see the
type's own comment on the mismatch between what `api.health.check()`
declares and what this panel reads) type; the `<img>` in
`AuthSessionGate.tsx` and the identical one in `PatientWorkspace.tsx`
(same static `public/` asset, same fixed-size CSS pattern) converted to
`next/image`; an `<img alt="Photo of ...">` corrected to drop the redundant
"Photo of" prefix; two ARIA-APG-correct focusable `role="separator"` resize
handles given narrow explained disables (the plugin's interactive-role list
doesn't include the movable-separator pattern); a `role="tablist"` container
changed from `<nav>` to `<div>` (the role already fully replaces its
semantics, and `<nav>`'s landmark meaning doesn't apply to a tab list); a
context menu given `tabIndex={-1}` plus focus-on-open so keyboard users land
inside it instead of needing to Tab in from wherever focus already was.

Reason: the goal was a trustworthy quality gate that catches real,
high-signal problems now (floating promises in an EHR's async order/sign/
audit paths, Rules of Hooks violations, invalid ARIA, dead imports) without
forcing either a suppression avalanche or an unrelated mass-rewrite across
~500 files to make day one green. Every "warn" above is a deliberate,
documented backlog, not an oversight — visible in `npm run lint` output,
non-blocking, and meant to be tightened to "error" rule-by-rule as each
backlog is worked down, not all at once.

Constraint: do not bulk-fix any of the staged categories mechanically
(especially `no-explicit-any` and the a11y interaction rules) without
reading each site — several genuinely need a real type or a real component,
not a cast or a suppression. Do not enable Stylelint or a repo-wide Prettier
run as a side effect of an unrelated change; both are their own dedicated,
mechanical-only PRs when taken on.
