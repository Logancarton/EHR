## Decision

The owner requested recovery, functional testing and repair of the unfinished
prescribing, signing, date-display and companion-fit work. Signing summarizes the
same visit-readiness groups shown beside the note; it introduces no second checklist
or clinical source of truth. Open, loading and unavailable groups remain distinct.

The sign dialog presents unresolved items and their existing review actions. When
readiness is open or cannot be fully checked, signing requires an explicit clinician
acknowledgement. A changed readiness summary invalidates the prior acknowledgement.
This is review assistance, not an assertion that the patient is clinically ready or
that an external integration is available. Existing server signing, authorization,
patient-binding and immutable-record protections remain authoritative.

The sign request may include bounded acknowledgement metadata. This records the
client projection the clinician acknowledged; the server does not recompute or
certify readiness. It must not be interpreted as an independent clinical attestation
or a verified completeness gate. Note signing never authorizes or transmits orders.

## Validation and remaining boundary

Focused domain tests cover loading/failure semantics, grouped unresolved items,
acknowledgement invalidation and untrusted metadata parsing. Browser tests exercise
the dialog, return to review and explicit acknowledgement. Final repository checks
and UI evidence must be recorded before claiming the recovered slice complete.
Server-owned readiness certification and atomic chart/sign coordination are outside
this bounded recovery.
