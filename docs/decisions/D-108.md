# D-108 — A companion draft belongs to the patient it was typed for

Decision ID: D-108
Date: 2026-09-26
Architectural status: Active / Accepted
Implementation status: Implemented in CB-6c.
Amends: [D-098](./D-098.md) (extends "never silently retargets" from patient-bound tools to the drafts of practice-level companions)
Amended by: —
Supersedes: —
Related decisions: [D-089](./D-089.md), [D-096](./D-096.md), [D-102](./D-102.md)

## Context

D-098 parks a patient-bound companion (Clinical AI, rating scales, Labs) when another
chart comes forward, so it cannot act on the wrong patient. Tasks, Scratchpad and
Messages are not patient-bound tools: they stay live across charts and act on the chart
in front. Each held its composer text as one string for the whole workspace, so the
text survived a chart switch while the patient it would be saved against changed.

Reproduced in the browser on `bc31d56`: "Recheck Maya's lithium level", typed into Tasks
on Maya Chen's chart, was filed against Jordan Reed after switching to his chart and
pressing Add. A Messages reply typed in Maya's thread sat in a composer relabelled
"Reply to Jordan Reed…" and would have been sent in his thread. A Scratchpad note's
"For" picker followed the new chart while the text stayed. Nothing on screen reported
the change of owner.

## Decision

A companion draft is held per scope: the patient whose chart was in front when it was
typed, or the practice when no chart was. Changing charts changes which draft is shown;
it never moves a draft to another patient. Returning to a chart brings its draft back.

- A save reads the draft's scope when it starts. A chart switch while the save is in
  flight cannot redirect it, and success clears only the draft that was submitted.
- A failed save keeps the draft in its own scope.
- A draft's explicit target travels with it. A Scratchpad note marked "Practice note"
  stays a practice note across chart switches.
- A reply belongs to one patient's one thread; the open thread is remembered per patient.
- The docked Tasks composer states the patient a new task will link to ("Links to …",
  or "Practice task — no patient"), so the clinician does not infer it from the tab strip.

`app/lib/use-scoped-drafts.ts` is the one helper for this; `useCompanionWorkingData`
and `PatientMessages` use it. Tools that already bind an explicit target (Communication,
Labs) or park (D-098) are unchanged.

## Consequences

- A new companion that holds typed text across chart changes must scope it the same way,
  or bind an explicit, visible target.
- Drafts are held in memory for the life of the companion's owner. The Messages reply
  and open thread are held there too, so they survive a tool switch (CB-6d). Continuity
  across a page refresh for all three tools is still CB-6 work.
