# D-115 — Document-first LIVE capture and separate provider guidance

Decision ID: D-115
Date: 2026-10-02
Architectural status: Active / Accepted
Implementation scope: ENC-LIVE-1 bounded deterministic foundation
Amends: [D-100](D-100.md), [D-114](D-114.md) (capture editing and rail placement)

## Decision

Encounter derives explicit LIVE, REVIEW and SIGNED presentation from capture activity and the existing encounter status. LIVE renders narrative and MSE prose read-only. Stop, capture failure, demo completion or reopening ends capture; REVIEW permits ordinary document editing. SIGNED continues through the existing server signing ceremony, immutable snapshot and amendment boundary. Capture is never restored as an active microphone after reopening. It is a local input session, not a server lock or permission grant.

The document occupies the main column; Provider Copilot and existing Clinical / Note Tools / Scribe share the right rail. Existing source-backed context, monitoring controls, prescribing/lab composers, history and tool access are retained. Readiness moves to a bottom completion strip and expands in place. Its status/counts remain projections over existing owners, with loading/unavailable states. Provider-attested **note-section coverage** is separate from operational readiness: it cannot mark orders, medication work, billing or follow-up complete.

Guidance is explicitly targeted to a note section and typed as correction, observation or clinical thought. Corrections replace the selected interpretation and retain previous wording; observations append clinician findings. Clinical thoughts remain in guidance history, excluded from note prose and diagnosis truth. This is explicit clinician wording, not semantic interpretation of arbitrary commands. Withhold clears a premature section interpretation, retaining its previous wording and withholding subsequent capture additions for that section until corrected. A clarification flag and considerations keep a section uncertain until reviewed. The existing optional synthesis path leaves all sections with guidance untouched, including empty sections intentionally withheld from characterization.

Guidance and coverage attestations are separate typed arrays in the draft transport, stored as individual append-only rows in `encounter_provider_guidance` and `encounter_coverage_attestations`. Transcript stays in the existing working-state owner; note sections remain in existing encounter columns. The authenticated server actor records authorship. Omission cannot delete guidance; changing an existing event is rejected before the draft write. Draft, working state, guidance and search indexing save atomically. Existing patient access, actor binding and optimistic revision checks remain in force. Signing rejects subsequent draft changes, including guidance. The signed snapshot's established shape/hash is unchanged.

Coverage is missing, partial, clarification-needed or covered. Text alone establishes only partial coverage. A clinician attestation references exact current section evidence; editing invalidates its sufficiency projection. Safety requires nonempty documented evidence and explicit attestation that SI, HI and self-harm were assessed. Quiet transcripts and normal MSE text cannot supply this attestation. These controls are documentation support, not a clinical risk formulation or a new signing-policy gate.

## Honest capture capability and remaining coupling

The live renderer is a replaceable, conservative deterministic function: captured utterances become attributed verbatim quotations. It does not infer normal findings, diagnoses or medication changes. Synthetic demo transcripts are explicitly labeled and limited to their matching synthetic patient. Browser speech recognition has no speaker diarization or production ambient assurance; captured evidence is preserved without vocabulary rewriting. Capture callbacks and optional synthesis responses carry session/encounter guards; stopped or foreign-session responses cannot overwrite a reviewed draft. Repeated demo evidence is deduplicated rather than erased.

This improves bounded visit state, provenance, provider control, output grounding and validation. It is a **bridge step**, not finished semantic psychiatric scribing. Core coverage adds medication response/tolerability only when the authorized snapshot shows active medications. It does not implement diagnosis/monitoring/visit-type adaptive domain coverage, sensitive-interpretation detection, model instruction-following, production audio capture, longitudinal plan reasoning or new monitoring rules. Free-text corrections require an explicit section and contain the clinician's replacement wording. Motor observations use the existing behavior MSE field rather than a parallel examination schema. Medication truth, prescription intent, orders/results, measures and signing retain their current owners. No paid service or new dependency is introduced.

Capture is local to a mounted encounter surface: another independently mounted pane/session is governed by existing revision conflicts, not a capture lease. Chart and monitoring projections remain independent reads; focus/manual refresh is still necessary for another browser's updates. The next bounded step is section/evidence-aware live drafting through the existing scribing interface, with structured output and guidance precedence tests; it must preserve the explicit capture/review boundary and avoid presenting inference as evidence.
