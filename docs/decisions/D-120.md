# D-120 — Responsive companion fit preserves clinician layout intent

Decision ID: D-120
Date: 2026-10-04
Status: Accepted
Amends: [D-116](D-116.md)

## Decision

Owner accepted the responsive companion improvement first. Use the existing companion controller and frame, without another navigation, patient, or draft owner.

Measure available root layout width in CSS pixels, including root enlargement. Reserve 720px for the primary canvas plus the existing 52px rail; cap the effective docked width to remaining space. If even the existing 260px minimum dock cannot fit, present a single companion surface below the measured persistent tab strip. Keep the rail reachable and provide a labeled Return to workspace action, using the existing close lifecycle with focus returned to its launcher. The covered primary canvas is inert for keyboard/accessibility interaction; practice-module shells outside that body are hidden without unmounting. Short/enlarged windows keep the toolbar in a bounded scroller so it cannot consume the entire working body.

Automatic fit does not store a new width, toggle the clinician's explicit docked/expanded preference, switch patient context, or remount the companion. Explicit expansion/redocking remains available. Resizing back restores the preferred docked width within the available space. Explicitly closing retains each tool's established draft/selection lifecycle; this does not promise local unstaged lab forms survive a close.

## Boundaries and risks

This improves presentation, accessibility and validation, not clinical authority, reasoning, permissions, transport or reconciliation. Existing patient-bound stores, stale-response rejection and authorized clinical gateways remain authoritative. Width thresholds are an initial tested geometry policy, not a font reduction or a new configurable density system. Detached/floating patient windows retain their existing independent ownership and are not reorganized by this slice.

Root geometry, globally loaded CSS and measured workspace chrome remain coupled; browser coverage must include ordinary narrow viewports, root enlargement and round-trip resizing. Cross-browser and full clinic-day certification remain separate gates. Transient opening of unpinned tools, medication information hierarchy and compact History controls are separate slices.
