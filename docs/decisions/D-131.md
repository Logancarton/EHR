# D-131 — The Overview reads as one list of highlights

Decision ID: D-131
Date: 2026-10-08
Architectural status: Active / Accepted
Implementation scope: Owner request 2026-10-08 ("organize the whole thing like Needs attention… highlights with click / expandable data")
Amends: [D-113](D-113.md) (layout, card width control, where diagnoses appear)
Related decisions: [D-104](D-104.md), [D-130](D-130.md)

## Context

The Overview had grown to about five screens of mixed cards. The same facts appeared two to four times (lithium monitoring, PHQ-9, diagnoses, the unsigned draft). Empty categories took a row each. Every card had a different header and action style, and short cards beside tall ones left gaps in the two-column grid. The owner asked for the same structure the Needs attention list had just been given: highlights first, detail on click.

## Decision

The Overview is one column of sections that share one anatomy:

- **Order:** Needs attention → a **Now** row of four tiles (Medications, Measures, Labs, Visits) → **Recent changes** → **Background** (history in one line per area, then care team).
- **Section header:** title on the left, at most one text link on the right ("Meds →", "Scales →", "Labs →", "Schedule →", "Timeline →", "History →"), and a ⋮ menu. No grey label above the title, no drag handle.
- **Lines:** each fact is one line with its key value first and the date right-aligned. A line with more to show expands in place to the full record: regimen and every monitoring rule, score history, flowsheet, reference range and review status, full history entries, the signed plan.
- **Provenance** (source system, source reference, recorded by) appears in the expanded detail behind an ⓘ, never in the highlight.
- **Color carries meaning only:** amber for a flagged monitoring status or abnormal result, red for critical. Normal lines stay neutral.
- **Empty areas:** all unrecorded history categories collapse into one "Not recorded" line. Care-team gaps collapse into the care-team line.
- **Diagnoses** are shown once, in the header Problems bar, which every chart section already shows. The bar lists three problems; "+N more" opens the full list, and each chip carries its code on hover. The bar now refreshes when the patient's record changes elsewhere, since it is the chart's only problem list.
- **Layout controls:** the existing card preferences are reused. Tiles can be pinned, moved earlier or later (menu items replace drag-and-drop), collapsed and hidden with visible restore. Recent changes and Background can be collapsed and hidden but keep their positions. The width toggle is retired because the tile grid sets widths: four across on a wide pane, 2×2 on a standard pane, one column when narrow. Saved `cardSpans` and `showDiagnoses` values are kept but no longer read. An untouched previous default order upgrades to the new one; custom and pinned orders are kept.

The sources, the patient-binding and stale-response rules, and the D-113 statements about history, screening results, safety plans and order projections are unchanged.

## Consequences

- The page for the synthetic David Kim chart drops from about 3,200 px to about 1,600 px at 1440×900 with a companion docked, with no source fact removed.
- Browser tests that addressed cards by their old titles were updated to the new titles and structure. They assert the same facts.

## Not done

Account balance and payments still wait for P9 (no billing category in Needs attention or the Overview until a balance source exists). The Overview does not yet offer a per-section "show everything expanded" control.
