# D-118 — Patients launcher requires deliberate chart selection

Status: Accepted · 2026-10-03 · Owner-directed correction to TAB-05.

## Context

The `+` launcher offered Patients but reopened the active chart (or selected the first roster patient). That made the entry behave like an implicit patient choice rather than a place to find a patient.

## Decision

Patients opens a search/selection canvas over the existing authorized roster. Search by recorded name, MRN or DOB; show patient identity before opening. Only an explicit result selection opens or focuses a chart through the existing navigation controller. Closing returns to the originating workspace without changing patient focus. Existing recent-patient shortcuts remain direct chart-opening actions.

Reuse the roster's permission filtering, loading/error/empty distinction and stale-response rejection. The picker owns only transient search/presentation state; it creates no clinical record, second patient store or persistent directory tab. Preserve mounted work and existing tabs while selection is pending. Native modal focus containment, explicit Close, Escape dismissal and focus return keep the selection canvas keyboard reachable. Launcher geometry must respect viewport bounds and root enlargement.

## Consequences and validation

This is a bounded presentation/navigation repair. Clinical permissions, persistence and AI behavior remain under their existing owners. D-085's universal launcher and D-117's shell ownership remain governing.
