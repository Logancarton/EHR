## Decision record

Date: 2026-09-19.

Status: accepted.

Decision: Collapse the global shell from three visual chrome rows to two levels. Level 1 is one unified top bar containing brand/home, labeled work navigation, the universal omnibox, and account/preferences controls. Level 2 is the persistent browser-style patient/workspace tab strip. The dedicated full-width work-navigation row introduced by D-070 is retired.

Phase 1 is deliberately presentation-only. `ToolNavigation` keeps its existing destination routing, keyboard behavior, event contracts, badges, test selectors, and authoritative workspace-navigation controller. It is mounted inside `WorkspaceTopBar` rather than reimplemented with local state. Persistent workspace tabs remain owned by `usePersistentWorkspaceTabs` / the patient workspace model. The contextual right companion rail and detachable patient windows remain intact.

Reason: the separate global bar, work-menu bar, and browser-tab bar created unnecessary vertical hierarchy and made the application feel like several navigation systems stacked together. The owner direction is a lighter Chrome/Google-Workspace-like shell where global navigation and search share one calm surface while open work remains a distinct persistent tab level.

Constraints:

- Do not install Tailwind or another UI framework to achieve this visual transition; use the existing CSS/token system.
- Do not invent a second navigation state model inside the header.
- Preserve readable labels, keyboard access, focus return, and menu dismissal behavior.
- Preserve Calendar as a first-class persistent workspace under D-072.
- Preserve the destination/configuration semantics recorded by D-083; this decision changes placement and hierarchy, not clinical authority or routing ownership.
- Broader calendar decluttering, tonal surface conversion, event-chip styling, and companion-pane refinements are later slices and are not implied complete by Phase 1.

Consequences: the shell reclaims the height of the old work-menu row and makes the open-work tab strip the only second chrome level. The historical `three-row-shell` CSS class may remain temporarily as a compatibility hook while feature-owned styles and tests migrate; its name is not the governing product model.


## 2026-09-20 amendment note

D-085 keeps the two-level chrome but changes the durable role of Level 1: labeled work-navigation controls are transitional during migration, while Home and the tab-strip `+` become the durable major-workspace access paths. Old controls remain until replacement parity is proven.
