## Decision record

Date: 2026-09-18.

Status: accepted.

Decision: Replace the loosely typed, string-based browser event bus and distributed state machine (`ehr-switch-view`, `ehr-global-module-close`, raw `window.addEventListener`/`window.dispatchEvent`) with an authoritative, typed `WorkspaceNavigationContext` / `useWorkspaceNavigation()` controller and a centralized typed event coordination layer (`app/lib/workspace-events.ts`).

Key architectural decisions:

1. **Commands vs Notifications Separation**:
   - **Commands ("Please make the application do X")** are modeled as explicit controller methods on `WorkspaceNavigationController`:
     - `openHome()`, `openToday()`, `openCalendar(date?, daysLater?)`, `openPatient(patientId, section?, mode?)`, `openGlobalModule(moduleId)`, `closeGlobalModule(moduleId?)`, `closeModuleTab(tabId)`, `openCommunications()`, `toggleCommunications()`.
     - Direct callers across UI components (`DynamicSidebar`, `TodayDashboard`, `PracticeQueueWorkspaceShell`, `GlobalWorkspaceShell`, `TeamCollaborationDock`, `CareCompletionDashboardWindow`, `IntakeWorkspace`, `OmniboxPlannerBridge`) use `useWorkspaceNavigation()` directly instead of broadcasting arbitrary browser events.
   - **Notifications ("X happened; interested consumers may refresh or respond")** remain decoupled events, but are unified under a single typed contract: `WorkspaceEventMap` in `app/lib/workspace-events.ts`.
     - Runtime validation type-guards (`isCalendarJumpDetail`, `isSwitchViewDetail`, `isEncounterSignedDetail`, `isInsertToNoteDetail`, `isSelectDocumentDetail`, `isDocumentWorkflowUpdatedDetail`, `isPatientUpdatedDetail`, `isOrderCartUpdatedDetail`) guarantee type safety at runtime.
     - `subscribeWorkspaceEvent` automatically runs the appropriate runtime guard before delegating to the callback, safely dropping malformed external or untrusted browser payloads without crashing or corrupting application state.
     - Automatic listener cleanup in React components via unsubscribe callbacks in `useEffect`.

2. **Headless / Utility Bridge Without Programmatic Clicks**:
   - `registerNavigationController` in `app/lib/workspace-navigation.ts` bridges the React navigation controller to non-React callers.
   - `navigateToLocation` and `navigateToPatientLocation` invoke the registered controller directly. They only fall back to DOM selector queries and programmatic `.click()` as an emergency fallback if the React tree is unmounted.

3. **Authoritative Encounter Signing & Single Notification Point**:
   - Resolved the dual-dispatch defect: `EncounterWorkspace.tsx` is established as the sole authoritative dispatch point for `ehr-encounter-signed` upon successful server persistence (`/api/encounters/[id]/sign`).
   - The redundant secondary dispatch in `PatientWorkspace.tsx` was removed. Downstream subscribers (`TodayDashboard`, `CareCompletionDashboardWindow`) receive exactly one notification per signed encounter.
   - Server persistence remains authoritative clinical truth; UI refresh events only signal post-commit coordination.

4. **Preserved Boundaries & Elimination of Dead Pathways**:
   - **Patient Identity Safeguards**: `ehr-insert-to-note` and `ehr-select-document` strictly validate target patient IDs so content or documents intended for one chart can never be routed to another.
   - **Calendar Coordination**: `calendar-jump-date` remains a typed coordination event consumed by both `CalendarWorkspace` (main schedule view) and `CalendarCompanionPanel` (docked companion rail), ensuring consistent interval jumping across whichever surface is active without duplicating scheduling state.
   - **Dead Event Elimination**: Deprecated/dead events (`ehr-nav-back`, `ehr-nav-forward`, `ehr-toggle-team`, `ehr-linked-patient`) were removed and replaced with direct controller calls.
   - **Browser DOM Gestures**: True browser events (keyboard, resize, and bubbling DOM pointer events in `FloatingPaneController`) remain native DOM events.
   - **Architectural Hygiene**: All application components in `app/components/` are free of raw `new CustomEvent("ehr-...")` and `addEventListener("ehr-...")` calls, verified by `tests/event-coordination-hygiene.test.ts`.

Reason: Global string-based custom events routed through `window` turned application navigation into an implicit, untyped distributed state machine with subtle race conditions, duplicate notifications, and DOM click hacks. Migrating to an explicit controller and a typed notification channel makes navigation discoverable, testable, type-safe, and architecturally clean without introducing external state-management libraries.
