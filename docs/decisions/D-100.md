# D-100 — Visit readiness is a projection beside the note, not a second checklist

## Context

The owner asked for prompts built into the note: missing information, what billing and insurance need, lab reminders, medication reminders. The facts behind those prompts already existed in three places a clinician could not see while writing — the coding engine's documentation goals (a collapsed footer), the care-completion rules (a separate dashboard board), and the billing charge blockers (evaluated only after the note was signed). The owner also asked for the note to feel like Google Docs rather than a form builder.

## Decision

1. **One readiness panel sits in the note's right margin**, grouped Note · Billing & insurance · Labs & monitoring · Medications · Follow-up. Every item names where its fix lives and acts: focus a section, open the therapy-time control, open a chart tab, the schedule, Billing, or the patient's administrative record.
2. **It is a projection, never a store.** `app/domain/visit-readiness.ts` derives every item on each render from sources that already own the fact: the draft and `calculateEncounterCoding` goals; `GET /api/visit-readiness`, which assembles care-completion items for one patient (`careCompletionService.patientItems`, the same rules the board uses), coverage completeness from the recorded policies, the encounter's coded diagnosis links, and the practice's billing setup. Nothing is checked off by hand; an item closes when its source changes.
3. **Medication surveillance is D-099's.** The Labs group evaluates the effective monitoring policy against the same evidence mapping the chart Overview uses (`monitoringEvidenceFromRecord`, now shared). Care completion's older `monitoring-labs` catalogue is deliberately excluded from the panel so a clinician never sees two answers to one question.
4. **Failure is stated per part.** Each server part (care, monitoring, coverage, billing) fails on its own; a missing or failed part renders "Could not be checked … not the same as nothing to do". A response is discarded unless it belongs to the patient and encounter currently open.
5. **Billing prerequisites move before signing.** Coded diagnosis links, psychotherapy time for an add-on, a charge template, a practice fee, and the rendering provider's NPI are visible while writing (D-101 supplies the last three).
6. **A signed note's gaps are history.** After signing, note-owned items become information, not open work; practice and chart items stay open.
7. **Note flow.** The rail's phrase tool becomes *Suggestions* and follows the cursor (all categories stay mounted so unfinished wording survives); *Focus* hides tools and collapses readiness to its count; on a narrow pane readiness starts as a one-line bar. The documentation-and-coding review moved from the footer into the Billing group. The outer note containers use `overflow: clip` so focus and `scrollIntoView` can no longer slide the toolbar away.

## Consequences

- No new table and no new rule set. The only server additions are a read route and `patientItems` over existing rules.
- Opening Review & Sign now extracts references from the flushed Assessment and Plan first, and a brand-new note re-runs extraction when its first save lands; before this, a note signed within the extraction pause, or never re-extracted after its first save, reached signing with no proposed diagnosis links.
- Administrative drawer saves now announce `WORKSPACE_PATIENT_UPDATED_EVENT`, so coverage edits refresh readiness without a manual re-check.
- Readiness collapse is a per-viewer browser preference; it never hides the open count.

## Evidence

- `tests/visit-readiness.test.ts` — derivation, closure on edit, per-group failure, missing parts, signed-note behaviour, D-099 monitoring, coverage wording, route access and wrong-encounter refusal.
- `tests/browser/visit-readiness.spec.ts` — prompts focus the section and close when written, a 500 is reported per group, Focus keeps the count.
- `tests/encounter-reference-failure-semantics.test.ts` — the degraded-provenance label moved into the readiness model and is still asserted.
