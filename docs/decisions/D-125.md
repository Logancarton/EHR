# D-125 — Review repairs preserve source and workspace ownership

Decision ID: D-125
Date: 2026-10-06
Architectural status: Active / Accepted
Implementation status: Implemented; validation evidence is tracked in ROADMAP_COMPLETED.
Amends: [D-117](D-117.md) (practice queue tabs), [D-124](D-124.md) (navigation versus review completion)

## Decision

The owner authorized fixing the improvements discovered by REVIEW-LOOP-1. Results Queue and Document Inbox are independent practice workspaces and use the existing module-tab lifecycle. The existing provider workspace snapshot saves eligible open module IDs and the active module. Restoration uses the registered navigation controller; it does not introduce a new router or grant access. Older snapshots safely default to no saved module tabs. Every clinical read/action still enforces the user's current authority.

The patient's shared working order cart feeds the note and monitoring views through existing patient-bound section actions. Its display is explicitly local drafts, not orders placed in the encounter or evidence of authorization/transmission. Navigation through Review & Sign is not a completion attestation. An empty note does not expose or persist the default code as an evidence-supported estimate; the existing coding calculator and clinician signing boundary remain.

Assessment item-level flags generated by the existing instrument rule are visible before all items are answered. Overall severity remains incomplete and saving still requires the complete instrument. No risk policy or medical threshold changes.

Chart recap is a deterministic projection of the permission-aware assembled context's recorded diagnoses, medications and allergies, with source references. It states its bounded scope and does not infer a clinical formulation. Missing supporting references suppress the corresponding values. This is a bridge capability, not semantic chart synthesis. The current parallel value/provenance ordering is coupled to ContextAssembler and must stay aligned.

The model boundary rejects laboratory proposals when a medication operation was requested without laboratory language. This is lexical containment, not proof of intent understanding; explicit mixed medication/laboratory requests and ordinary human review remain supported. Richer semantic intent validation remains open.

Retired communication fixture snippets are archived as non-authoritative history. Legacy components remain for imports and containment tests, with no fabricated incoming clinical messages or fax delivery confirmations. Canonical Communication remains the owner. Seeded patient-task links and the corrected synthetic allergy example affect new databases; existing clinical records are not silently rewritten.

## Limits

The medication catalog remains limited; search does not add a drug database. The practice timezone remains shared configuration. Local order-cart/session authority, per-file browser database isolation, complete browser/CI certification and external transport remain existing separate gaps. No paid integration or hosted model is enabled.
