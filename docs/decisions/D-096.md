# D-096 — The foreground canvas owns implicit companion context

Decision ID: D-096
Date: 2026-09-22
Architectural status: Active / Accepted
Implementation status: Implemented in UI-9. Companion patient binding and layout-customizer scope are derived from one active-canvas identity; focused unit and browser coverage pass.
Amends: [D-085](./D-085.md)
Amended by: —
Supersedes: —
Related decisions: [D-035](./D-035.md), [D-080](./D-080.md), [D-081](./D-081.md), [D-093](./D-093.md)

## Decision record

The selected patient tab is durable by design. Before this decision, that remembered
patient was also passed directly into the right companion and omnibox even when Intake,
Calendar, Dashboard, Home, or another practice workspace was visibly in front. The
communication header could therefore say `Context: Maya Chen` beside the Intake queue,
and patient-bound companion mutations could inherit that background chart. Separately,
the Layout Customizer always opened on Today Dashboard, even from Maya Chen's Documents
surface.

Those are two symptoms of one missing rule: **the foreground canvas owns implicit
context.** Remembering a chart is not the same as making it the active execution target.

### One derived canvas identity

`deriveWorkspaceCanvasContext` now resolves the active canvas with this precedence:

1. a foreground global/practice module;
2. the active patient chart and its section;
3. Today, Calendar, Home, or an empty patient workspace.

The result carries a stable tab/canvas identity, a visible label, an optional patient
id only for patient canvases, and the matching layout-customizer scope. A module wins
over the remembered chart underneath it. The shell derives this once and passes it
down; no second router, tab store, or companion state owner was added.

### Companion behavior

- Patient identity reaches Clinical AI, patient Messages, rating-scale persistence,
  scratchpad/task creation, the omnibox, and active-chart order actions only when the
  patient chart is the foreground canvas.
- Communication changes to a visible workspace context such as `Context: Intake
  workspace` instead of retaining the background patient's name. A draft's explicitly
  selected patient/recipient remains selected and visible in its own control; it is not
  silently retargeted or erased.
- A patient Messages panel opened on a practice canvas stays present but refuses the
  chart-bound work and explains how to recover it, instead of disappearing or using the
  remembered chart.
- Prescribing's explicit patient selector remains explicit and independent, as D-093
  requires. This decision removes implicit patient inheritance; it does not prohibit a
  tool from deliberately selecting a patient of its own.

### Layout Customizer behavior

The customizer names the canvas it is configuring and opens on the relevant scope:

- Today -> Today Dashboard;
- patient chart sections -> Patient Chart;
- Encounter -> Encounter Note;
- practice workspaces, Calendar, and Home -> Density & Shell.

Clinicians may still move between customizer tabs. Opening the drawer again re-derives
the starting scope from the current canvas rather than retaining a stale local default.

### Architectural assessment

This is a deeper workspace-context step, not a route-shaped containment patch. The
improved layer is presentation/workspace context ownership and the clinical-safety
boundary that feeds patient-capable peripheral actions. It does not change clinical
record authority, create per-tab copies of companion drafts, or finish the broader
companion lifecycle certification in CB-6. Explicit tool-owned targets remain possible
and must remain visible.

### Evidence

- `npm run check`: exit 0; lint and typecheck pass; 445/445 unit tests pass.
- `npm run build`: exit 0.
- `tests/workspace-canvas-context.test.ts`: four rule-level cases cover module
  precedence, patient/section binding, customizer mapping, and the absence of patient
  ids on workspace canvases.
- `tests/browser/workspace-context-alignment.spec.ts`: 2/2. It drives Maya Chen ->
  Communication -> Intake and proves the companion changes from the patient tab to the
  Intake canvas; it also drives Maya Chen -> Documents -> customizer and then Intake ->
  customizer, proving the matching scope and visible context at 1440x900, 1280x800,
  1024x768, and 720x450.
